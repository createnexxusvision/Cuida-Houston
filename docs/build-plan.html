Cuida HOU · PRD + TRD · v0.2 · Sept 26, 2026

Cuida HOU build plan

A bilingual, two-sided childcare network for Houston. Door 1 helps parents find licensed care they can reach. Door 2 guides women in childcare-desert ZIP codes through opening a licensed home daycare.

OwnerDanny Arzu
ContextImpact Hub Houston hackathon 2026
SDGs5 · 8 · 10 · 11
StackAll AWS: Amplify · Aurora Serverless v2 (PostgreSQL + PostGIS) · Lambda

Verdict

The hackathon prototype is buildable in 48 hours on public data. The core state licensing dataset is open, public domain, has an API and was updated September 15, 2026.

The bigger risks come after the weekend: real-time open-seat data, the legal accuracy of the provider pathway, deed restrictions on home businesses, and whether a support partner will take the handoff. None of these stops the prototype. Several could stop the pilot.

Fix before you pitch: slide 4 has a logic error

The ~30,000-family waitlist is for subsidy funding, not seats. Adding home providers adds seats in desert ZIP codes, but it does not shorten a funding waitlist. Pitch the provider side as a fix for deserts and working mothers, and cite the waitlist only as evidence of unmet demand.

Read first

Issues that could stop the project

Resolve these first. Each could block a stage outright, not just slow it down.

B1 · mostly resolved

Hackathon rules

Own challenges are accepted. Submission is due Sunday 9/27 at 11:45 a.m. Central. Code ownership is still unconfirmed; ask before adding a license.

B2 · blocks the "open seats" promise

No public vacancy API

The state dataset has licensed capacity, not open seats. The Texas Workforce Commission (TWC) portal shows open seats, but I found no public API or download. Without a data-sharing agreement, the parent side shows capacity and asks parents to call.

B3 · blocks Door 2 at pilot

No partner to take the handoff

The app can guide a woman to the licensing forms, but coaching, training and startup costs need a partner. Without one, Door 2 is a checklist and sign-ups stall.

B4 · blocks individual providers

Deed restrictions

Houston has no zoning, but private deed restrictions can prohibit home businesses, and the City enforces them. A would-be provider could complete licensing steps and then be barred by her subdivision.

B5 · legal exposure

Regulatory accuracy and liability

Wrong licensing guidance, or anything that reads as endorsing a provider, creates liability. All guidance must link to and date-stamp official Texas Health and Human Services Commission (HHSC) sources. Get a lawyer to review the disclaimers before the pilot.

B6 · team capacity

Who runs it after Sunday

The pilot needs a part-time coordinator and a Spanish content reviewer. As a solo founder running three LLCs, you need these roles named before promising partners a January pilot.

PRD · 1

Problem, goals and non-goals

Greater Houston has 44 childcare-desert ZIP codes, 28 of them chronic (Children at Risk, April 2026). In Houston, 60.4% of women 16 and older are in the labor force, compared with 67.0% of all residents (ACS 2019–2023). The city is 44.2% Hispanic and 22.3% Black. Search tools exist, but none of them grows supply where it is missing, and the path to becoming a licensed provider is hard to find, especially in Spanish.

Goals

  • Parents in desert ZIPs can find licensed care that matches their child's age, their hours and their commute in under two minutes, in English or Spanish.
  • Women in desert ZIPs can find out whether they could open a home daycare, and get a correct, current, bilingual step list plus a warm handoff to a support partner.
  • The City and partners can see unmet need by ZIP from public data they can check.

Non-goals

  • Booking, payments or enrollment. Parents contact providers directly.
  • Rating or recommending providers. The app shows state inspection data neutrally.
  • Processing subsidy applications. We link to Workforce Solutions and the state's application.
  • Collecting any data about children.
  • Any NextPlay Nexus integration. This project stands on its own.

Design principles

  • Mobile first, works on a slow connection, no login to search.
  • Plain language at about a 6th-grade reading level in both languages.
  • WCAG 2.1 AA: screen-reader labels, contrast, keyboard use.
  • Show where every number comes from and how old it is.

Everything runs on AWS. Amplify Hosting serves the Next.js app, including server-rendered pages and API routes. Aurora Serverless v2 (PostgreSQL with PostGIS) holds the data and handles distance queries. A Lambda function in Node 22, triggered nightly by EventBridge Scheduler, runs the data pipeline. Both reach the database through the RDS Data API over HTTPS, so there is no VPC or NAT gateway to set up or pay for. Secrets live in AWS Secrets Manager.

The web app logs in as cuida_web, a read-only role that can only run the search function and read reference tables. The pipeline uses the master login. Locally, the same SQL runs on Postgres + PostGIS through DATABASE_URL.

Need score

seats_per_100 = licensed_capacity_in_zcta / children_under6_all_parents_working × 100
desert        = seats_per_100 < 33.3        -- more than 3 children per licensed seat
need_rank     = rank by (desert, lowest seats_per_100, highest SVI)

This mirrors Children at Risk's public definition, but their exact method may differ, for example in how school-age capacity is counted. Compare our list of 44 ZIPs with theirs and explain any gap on the page.

Cleaning steps

  1. Keep active Harris County day-care types only.
  2. Normalize ZIP to 5 digits. Strip the TX- artifact from addresses.
  3. Parse hours into open_time and close_time. Mark - or blanks as unknown.
  4. Split licensed_to_serve_ages into an array.
  5. Hash each row. Geocode only new or changed addresses.
  6. For home operation types, round public coordinates to about 500 m and hide the street address in the UI.

Front end

  • Next.js App Router with locale routes (/es, /en) and a translation library such as next-intl. Every user-facing string lives in message files.
  • Map with MapLibre GL and a free vector tile source, or a static list with no map on slow connections.
  • Pathway content in MDX per language, with the source URL and verified date rendered under every step.
  • Privacy-friendly analytics with no cookies and no personal data.
TRD · 5

Privacy, safety and security

  • Home providers' addresses. The state publishes them, but republishing a woman's home address on a map is a different act. Show homes at approximate location with the phone number, and link to the official record for the full address.
  • No child data. Parents search without accounts. No names, ages of specific children or immigration-related questions are ever collected.
  • Provider leads (P1). Minimal fields, explicit consent naming the partner, encryption, deletion on request, retention limit (suggest 12 months). Have a lawyer check Texas privacy law obligations before collecting leads.
  • No endorsements. Present state data as-is, with a disclaimer that the listing is not a recommendation and families should visit and verify.
  • Fraud. Only list operations that exist in the state dataset. Self-reported seats must tie to a verified operation ID.
  • Security basics. Read-only cuida_web database role for the web app (tested in CI), master login only in the pipeline, dependency scanning, secrets in AWS Secrets Manager, least-privilege IAM roles for Amplify and Lambda, AWS Budgets alarm on the account.
